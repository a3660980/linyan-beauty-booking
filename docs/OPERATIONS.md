# 店家操作與維護

## 每日流程

1. 使用已授權的 LINE 帳號登入店家後台。
2. 查看待確認申請，核對日期、服務、金額、同行或前次服務資格。
3. 確認預約後，系統排程 LINE 成功通知。拒絕／取消會釋出時段並通知。
4. 到店收現金後，填寫實收金額，完成服務時標記「服務完成」。預約成功不代表已付款。
5. 定期檢查通知紀錄；「API 已受理」不代表送達或已讀。封鎖官方帳號者可能收不到訊息，客人仍可查詢我的預約。

## 排班與優惠

- 固定排班可分段，空白為休息；特定日期例外覆蓋週排班。
- 待確認申請占用服務與整理時間。逾時釋出由排程與查詢處理，最長受排程間隔影響。
- 兩人同行霧眉每人 $4,500。兩位使用相同同行預約識別碼，分別安排時段。未建立第二筆關聯預約不能確認優惠。
- 補睫需要原客人前次已完成美睫紀錄，限兩週內原款式；店家輸入核對後的半價金額。補色需要三個月內已完成霧眉紀錄。
- 無創除色由店家審核確認金額。不要把估價當成已收款。
- 手動新增的預約未綁定 LINE，請店家自行聯絡客人。

## 訊息與額度

提醒預設關閉，開啟後由每 10 分鐘排程處理明日前的通知。LINE 輕用量每月有免費訊息上限；可在系統 LINE 通知頁查詢本月剩餘額度，也可在 LINE 官方帳號後台查看用量，不足時關閉提醒、改以人工聯絡或升級方案。LINE API 429 可能代表頻率或額度限制。

失敗通知採退避重試，最多自動嘗試 5 次；後台可重新排程。不同通知種類只建立一次，避免重複確認造成重複推播。

## 匯出與備份

後台現金收款頁可匯出 CSV。下載後保存在私人裝置，禁止提交到公開 GitHub、Issue 或 Actions artifact。

D1 有平台備份／Time Travel，保留期限依方案而定。另可由管理員執行 `wrangler d1 export DB --remote --config .deploy/wrangler.json --output backups/private.sql` 保存至忽略的 backups 目錄；先建立目錄，定期驗證還原流程。不要由公開 CI 上傳 SQL 備份。

## 維護

每月檢查依賴更新與通知失敗。結構更新增加 migration；避免破壞已有預約。回退 Worker 版本不會自動回退 D1 migration。刪除或修正個資前核對申請人身分，保留必要操作紀錄，依店家訂定的保留政策處理。
