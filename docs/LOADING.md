# 資料載入狀態盤點

| 區塊 | 等待提示 | 失敗處理 |
| --- | --- | --- |
| 首次進站、重新整理 | 全畫面確認登入狀態；驗證完成才顯示登入或帳號介面 | 無法驗證時可重新載入，不判定為訪客 |
| 預約日期與時段 | 查詢時段中；等待期間不能前往下一步 | 原區塊顯示錯誤與重新查詢 |
| 我的預約 | 首次載入預約紀錄中；刷新保留原清單並顯示更新中 | 保留已取得的清單，提供重新查詢 |
| 後台預約、行事曆、客人、收款、設定、通知紀錄 | 共用後台資料載入提示；首次回應前不顯示 0 筆或空清單 | 原後台提供重新查詢；刷新失敗保留先前資料 |
| LINE 訊息額度 | 獨立顯示查詢／更新額度中 | 原區塊提供重新查詢 |
| 提交與取消預約、審核與儲存 | 送出中、取消中、儲存中；相關操作停用 | 顯示操作錯誤，不假裝成功 |
| LINE 發送失敗的重新排程 | 按鈕顯示重新排程中，避免重複提交 | 後台顯示操作錯誤 |
| 初始化服務與登出 | 初始化中／登出中，避免重複操作 | 可在原網站重試 |
| LINE 登入驗證失效、取消或失敗 | 返回原預約／我的預約／後台，網站內顯示重新登入提示 | 不將 OAuth JSON 錯誤作為獨立頁面；保留預約草稿 |

只有成功取得空清單才顯示「沒有預約」。刷新期間保留舊資料並停用資料操作，避免誤用尚未更新的內容。切換頁面或身分會取消不再需要的查詢；請求超過 15 秒終止等待，提醒先確認操作狀態再重試。登入逾期的 API 回應會移除舊身分並在原頁顯示登入提示。

瀏覽器測試以受控的慢速回應、查詢失敗、重試與空結果驗證以上情境；GitHub CI 同時使用 Chromium 與手機 WebKit。
